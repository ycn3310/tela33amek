# tela33amek

A Django web application for sharing and browsing **past exam papers**, organised by course, major, year, semester, establishment, teacher and exam type. Papers are uploaded as PDFs, either through the site/API or in bulk with a helper script.

- **Live site:** https://tela33amek.vercel.app
- **Repo:** https://github.com/ycn3310/tela33amek

> **Note for maintainers:** items marked **(verify)** were inferred from the repo structure and dependencies rather than read from the source. Confirm them and remove the marker.

## Tech stack

| Area | Tool |
|---|---|
| Language / framework | Python, Django 6.0 |
| API | Django REST Framework |
| Database | PostgreSQL in production (`psycopg`, `dj-database-url`); SQLite (`db.sqlite3`) locally |
| File storage | S3-compatible object storage via `boto3` + `django-storages` (PDF uploads) |
| Static files | `whitenoise` |
| Images | Pillow |
| Server | `gunicorn` (see `Procfile`) |
| Config | environment variables loaded with `python-dotenv` |
| Hosting | Vercel |

Exact versions are pinned in `requirements.txt`.

```
└── __pycache__/         # Python bytecode (should be git-ignored)
```

### What each part is for

- **`tela33amek/`**: project configuration. Start with `settings.py` to see installed apps, database config, storage config and environment variables used. `urls.py` is the root URL router.
- **`pages/`**: the main application code. Look at `models.py` for the data model, `views.py` for page and API logic, and `urls.py` for routes **(verify)**.
- **`templates/`**: Django templates rendered by the views.
- **`static/` vs `staticfiles/`**: edit files in `static/`. `staticfiles/` is generated by `python manage.py collectstatic`; do not edit it by hand.
- **`bulk_uploader.py`**: described below.

## Domain model (what a "paper" is)

Each uploaded paper carries this metadata (taken from the upload API / bulk uploader):

| Field | Meaning |
|---|---|
| `course` | Course / module name |
| `major` | Field of study |
| `year` | Study year |
| `semester` | Semester |
| `establishment` | School / university / institution |
| `teacher` | Instructor |
| `paper_type` | Type of paper (e.g. exam, test, etc.) |
| `cycle` | Study cycle |
| `session` | Exam session |
| `file` | The PDF itself |

## Getting started

### Prerequisites

- Python 3.12+ (use whatever version the team standardises on) **(verify)**
- `pip` and `venv`
- Optional: a PostgreSQL instance and S3-compatible bucket if you want to mirror production

### Setup

```bash
git clone https://github.com/ycn3310/tela33amek.git
cd tela33amek

python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate

pip install -r requirements.txt
```

### Environment variables

Create a `.env` file in the project root. The settings read configuration from the environment; check `tela33amek/settings.py` for the authoritative list. Typically for this stack you will need **(verify names)**:

```
SECRET_KEY=change-me
DEBUG=True
DATABASE_URL=sqlite:///db.sqlite3
# Object storage (only needed if uploads go to S3 in your environment)
AWS_ACCESS_KEY_ID=...
AWS_SECRET_ACCESS_KEY=...
AWS_STORAGE_BUCKET_NAME=...
AWS_S3_ENDPOINT_URL=...
```

Never commit `.env` or real credentials.

### Run locally

```bash
python manage.py migrate
python manage.py createsuperuser     # optional, for the admin
python manage.py collectstatic --noinput
python manage.py runserver
```

Then open http://127.0.0.1:8000.

## API

### `POST /api/upload-paper/`

Uploads one paper. Sent as `multipart/form-data` with the metadata fields above plus a PDF in the `file` field. Returns **HTTP 201** and JSON containing the new paper's `id` on success.

Example:

```bash
curl -X POST https://tela33amek.vercel.app/api/upload-paper/ \
  -F course="Algorithms" \
  -F major="Computer Science" \
  -F year="2" \
  -F semester="1" \
  -F establishment="Example University" \
  -F teacher="Dr. Example" \
  -F paper_type="exam" \
  -F cycle="licence" \
  -F session="normal" \
  -F file=@paper.pdf
```

Use your local server URL instead of the production one when testing.

## Bulk uploading papers

`bulk_uploader.py` uploads many PDFs through the API in one run.

1. Prepare a JSON file: a list of objects, each with the metadata fields above plus a `path` pointing to the PDF on disk:

   ```json
   [
     {
       "path": "/path/to/algorithms_2023.pdf",
       "course": "Algorithms",
       "major": "Computer Science",
       "year": "2",
       "semester": "1",
       "establishment": "Example University",
       "teacher": "Dr. Example",
       "paper_type": "exam",
       "cycle": "licence",
       "session": "normal"
     }
   ]
   ```

2. Run it:

   ```bash
   python bulk_uploader.py
   ```

   You will be prompted for the JSON file path and for an output file where failed uploads are saved.

3. Behaviour to know about:
   - Files that don't exist on disk are skipped.
   - Failed uploads are written to the output file after every item, so you can fix issues and re-run using that file as the new input.
   - If everything succeeds, the old failure file is deleted.
   - There is a short delay between requests to avoid hammering the server.
   - **The API URL is hard-coded to production** (`API_URL` at the top of the script). Change it to `http://127.0.0.1:8000/api/upload-paper/` when testing locally.

## Deployment

- The app is deployed to **Vercel** at https://tela33amek.vercel.app.
- `Procfile` defines the gunicorn process for Procfile-based platforms.
- Static files are served with WhiteNoise, so run `collectstatic` as part of the build.
- Production configuration (database URL, storage credentials, secret key) lives in the hosting platform's environment variables, not in the repo.

## Contributing workflow

1. Create a branch from `main`: `git checkout -b feature/short-description`
2. Make your change and run the app locally.
3. If you changed models, create and commit migrations: `python manage.py makemigrations`
4. Open a pull request against `main` with a short description of what and why.

## Things to be aware of

- **`db.sqlite3` is committed.** Treat it as local/dev data only. Avoid committing changes to it, and consider adding it to `.gitignore` (verify no real user data is inside).
- **`staticfiles/` and `__pycache__/` are committed.** Both are generated and normally belong in `.gitignore`.
- The bulk uploader targets the **production** API by default.
- There is no test suite documented yet **(verify)**; adding tests for the upload API is a good first contribution.
